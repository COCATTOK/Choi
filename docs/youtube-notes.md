# 유튜브 맛집 채널 분석 노트

대상: https://www.youtube.com/@matddori_ (2026-10-13 시도)

## 현재 상태: 자막 미확보 — 영상 내용 분석 없음

자막을 가져오지 못해서 **핵심 내용, 실행 방법, 주의사항을 정리하지 않았다.**
제목·목록만 보고 영상 내용을 추정해 적지 않는다. 자막을 확보하면 아래 "분석" 섹션에 추가한다.

## 확인된 사실

- 클라우드 세션 환경에는 유튜브 전용 MCP가 연결돼 있지 않다.
- `yt-dlp` 2026.08.19와 `youtube-transcript-api`는 `pip install`로 설치됐고 실행된다.
- `youtube.com` 접속은 가능했다(HTTP 200). 프록시 로그에 차단 기록은 없었다.
- 채널에는 **쇼츠 탭만** 있다(`videos` 탭 없음). `yt-dlp --flat-playlist`로 최근 30개의 ID와 제목은 가져왔다.
- `youtube-transcript-api`로 `EWJtMhbkpMk`의 자막을 요청하자 `RequestBlocked`로 실패했다.
- `yt-dlp --write-auto-subs`로 같은 영상의 자막을 받으려 하자 `HTTP Error 429: Too Many Requests`로 실패했다.
  node 런타임을 지정해 1회 재시도했지만 결과가 같았다.
- `yt-dlp`는 이 영상에 `ko`, `en-orig`, `en` 자막이 있다고 표시했다. 즉 "자막 없음"이 원인은 아니다.
- 시도한 영상은 1개뿐이다. 나머지는 요청을 늘리지 않으려고 시도하지 않았다.

## 추정 (확인되지 않음)

- 원인은 클라우드 IP에 대한 유튜브의 요청 제한 또는 차단일 가능성이 높다.
  두 라이브러리의 오류 메시지가 그렇게 안내하고, 메타데이터는 읽히는데 자막 요청만 막힌 양상과 맞는다.
  다만 유튜브 쪽 응답으로 직접 확인한 것은 아니다.
- 429는 일시적일 수도 있다. 시간이 지나면 풀릴지는 모른다.
- 도구 미설치, 실행 권한 문제, 자막 없음, 프록시 정책 차단(403/407)은 위 사실로 볼 때 원인이 아니다.

## 다음 방법 (선택)

1. 사용자가 영상 파일을 드라이브 폴더에 올린다. 화면과 자막을 함께 볼 수 있어 편집 분석에 가장 정확하다.
2. 사용자가 유튜브의 "스크립트 표시"에서 텍스트를 복사해 붙여넣는다.
3. 일정 시간 뒤 같은 방법을 소수의 영상으로 다시 시도한다.
